# AR3D Engine: new 3D Geo masterplan → plot customer workflow

This runbook is for **Engine** `building_geo` projects, not AR3D Platform's 2D map. Existing `legacy` projects keep their own immutable releases and historical geometry. No automatic conversion or project reset is performed.

## Manual workflow (owner)
1. **Overview → Create New Project → 3D Geo Masterplan + Plot Mapping.** Enter the project name and location. The new project opens **Project Profile** first. Set the optional project registration/reference number and Owner name, builder name, primary contact, full address, phone/secondary phone, WhatsApp, email, official Google Maps HTTPS link, and company/brochure links.
2. **Public contact visibility** is OFF by default. Enable the explicit checkbox only for numbers, owner name, addresses and other information the owner agrees to publish. Saving profile metadata does not itself publish a model or geometry.
3. **Source Pack → Building:** upload and review original CAD/PDF/source and the **GLB 3D masterplan**. Verify source ownership, model-local dimensions, axes, scale, floor/site plane and integrity. Create an immutable Building release. Upload does not automatically produce verified plot polygons.
4. **Geo:** Source → Place → Align → Fine Tune → Publish. Set WGS84 site location, heading and scale, verify independent real control points, then publish a verified Geo release. Google Maps browser key / Vector Map ID must be configured for the integrated map.
5. **Geo Plot Mapper → 01 Plot Inventory:** upload the approved Platform-format Plot Data CSV, including Plot IDs, Sqft/Sqm, Front/Back/Depth/Depth 2, Road Access and explicit CAD source notes. Review preflight, confirm inventory import. Area and measured sides are source-backed draft data, NOT automatically verified plot geometry.
6. **Start Next Unmapped:** click actual GLB/model-local plot corners. For normal plots begin with the real road-facing Front boundary and proceed around the polygon. For irregular/corner plots use Irregular, multiple edge assignment and source details. Confirm side lengths, facing, plane and reviewed sources; missing lengths must NOT be inferred. **Apply & Draw Next** for each.
7. **Save Mapping Draft → Data Quality → Verify All Plots → Preview Live vs Draft → Publish Mapping.** Only verified immutable geometry goes to the customer. Source/Geo revisions can make a draft stale and require a new review. Rollback activates a previously sealed mapping without editing historical rows.
8. **Commercial Facts:** manually set each plot's reviewed Available/Booked/Sold listing status, INR price if known, and actual signed/source reference. Approve public visibility only when authorized. No automatic availability, buyer identity, receipt/payment claim or sale record is inferred.
9. **Bulk Pricing CSV:** optionally upload `plot_id,from_id,to_id,pricing_type,unit,rate,fixed_price,currency` (the Platform sheet format). Exact Plot ID overrides matching ranges; different overlapping ranges are rejected. Rate calculations use source-verified published Geo plot area in sqft/sqm/sqyd. Preview then import as **private price quotes**; no status or public price is changed. Select a plot, use its reviewed quote, confirm signed source and explicitly save its commercial record. Only then can that price/status be shown publicly.
10. **Private deal records:** Owner and authorized Client Admin can record source-reviewed bookings, agreements, registration references and privately reported payments, with independent revisions and audit. This is not bank verification. Recording a private deal never changes the public plot status or price.
11. **Clients:** create a project contact directory record and issue a 24-hour, single-use invite. Viewer reads; Editor prepares private commercial updates; Approver/Client Admin can explicitly approve status/pricing. A client has no access to another project, Engine Owner sign-in, geometry publishing or private buyer/payment tables. Grant rotation/revocation immediately invalidates client sessions.
12. **Share & Branding:** upload/publish the shared circular logo/favicon; choose the **Geo** experience, upload the share poster, save share title/description, publish the Geo share card. The canonical HTTPS customer link is available only after the underlying Geo experience is published.
13. **Customer Geo site:** the verified 3D model is overlaid on Google Maps. The published polygons are clickable; plot ID, authoritative area, Front/Back/Depth, facing, road, notes and individually approved status/price appear in the plot details. When owner explicitly enables public contacts, the customer also sees approved builder/owner/address and Call, WhatsApp, Maps/website/email actions.
14. **Updates:** Owner can edit source inventory, geometry and other draft data, but must reverify and republish the mapping. Source-backed customer commercial data is updated by Owner or invited authorized Client Admin in the commercial portal; changed pricing is separately reviewed.

## Why this differs from the 2D Platform
- The 2D Platform maps normalized coordinates on an image. This Engine 3D workflow maps actual polygons in the **immutable model-local GLB space**, then uses a separate geographic alignment. Never treat CSV side lengths as automatically established 3D coordinates.
- The Engine supports source-reviewed status/INR listings, private range pricing and project-scoped booking/agreement evidence. It is **not** a bank-confirmed payment ledger and does not yet match the Platform's full domain management, daily automated plot notices or client geometry-authoring workflows. Those cannot be represented as verified without separate implementation and tests.
- Immutable Geo mapping version changes do not silently migrate public statuses/prices; re-review business data on the new source release.
- Client-editor authorization is limited by role and project. Plot geometry verification/publication and Owner-profile public-contact consent stay under Engine Owner control.

## Required real acceptance before a paying customer

Use the separate [evidence-backed launch acceptance procedure](geo-customer-launch-acceptance.md) to combine numeric source survey, real device screenshots, public social crawler bytes, full offline D1/R2 rehearsal and authorized isolated cloud restore proof. It deliberately requires a final independent owner signoff; a passing automated CI run is not physical certification.

- Survey at least ten independently measured control plots; compare every road-facing edge, model-local corner and Geo placement. Do not label a plan surveyed from synthetic or screenshot evidence.
- Try a fresh `building_geo` project end-to-end: new record, profile, GLB, Geo, Platform CSV, complete mapping, pricing, real logo, public share image and customer plot click. Test disabled contact consent and explicit consent separately.
- Run actual Android Chrome and iPhone Safari touch/performance tests plus in-app WhatsApp share preview (remote WhatsApp cache and crawler may vary). Test mobile and slow network behavior.
- Take full remote D1 + project R2 bytes backup and rehearse restoration into **isolated Cloudflare resources** with separate credentials. The existing local isolated SQLite rehearsal and SHA-verified bytes script alone are not a completed cloud disaster-recovery drill.
- Reopen and modify a published project, confirm old published snapshot does not shift until republish; test client role changes, revoked invitations, cross-project access and price-sheet conflict detection.

**Safety:** no AR3D Platform repo changes, no destructive demo reset, no verified buyer/payment claims and no silent publication of private contact data.
